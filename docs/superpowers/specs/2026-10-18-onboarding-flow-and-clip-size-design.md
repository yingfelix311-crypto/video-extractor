# 网站会话核查、新用户引导及剪辑尺寸

用户明确要求完整核查真实流程、提出并落实易上手设置，并修改链接快速清空及剪辑常用/原视频尺寸。沿用已接受的本地工具及按需授权设计，在当前任务分支继续工作，不增加另一轮形式性审批。用户已确认“预览与导出一致，默认原视频”，不覆盖源文件。最新要求：浏览器或 Cookie 与问题无关时，不添加对应必选配置，不以未经证实的推断引导登录、导入或授权。

## 事实与验证边界

- 粘贴 URL 只提供视频地址，不会带上复制来源浏览器的账号；会话来源由软件内已保存的浏览器/配置决定，与系统默认浏览器分开。
- Cookie 可能是访客、设备、偏好或登录凭证。读取成功只证明取得网站会话信息，不能证明用户登录，更不能根据 Cookie 名称推断网站认可当前登录。
- 当前用户设置为 Chrome/Profile 1；用户明确表示 Chrome 未登录抖音。接受该事实，不再推测用户登录过。
- 必须以新建空 jar 和当前所选浏览器会话，在相同 URL/请求方式下做只解析对照；仅输出数量、布尔值和提取结果，不输出 Cookie 值、个人资料或媒体签名地址。网站对不同请求的详细判断仍可能未知。

## 实施范围

1. 网站会话：用准确的“网站会话（可能为访客状态，账号登录未验证）”取代“同步账号”的暗示。入口说明链接来源与会话来源的关系。新增本机读取检查，仅检查对应平台数据是否可读，不冒充网站登录验证。已授权自动读取失败时保留原始错误，并提供本次不读取浏览器信息的重试入口，不偷偷改持久开关或改换浏览器。
2. 新用户：默认允许直接粘贴公开链接，自动读取仍需用户主动开启。设置中的浏览器明确为“会话来源浏览器”；只有多配置时强调选择账户配置。提供可跳过、可重开的快速上手，涵盖后台环境、视频/音频与画质、保存位置、可选会话、失败恢复、剪辑。手动文件、代理和请求头归入高级设置。现有 Colima/Docker/MeTube 依赖必须明确，不能宣称可在任意新 Mac 上独立即用。
3. 输入：主输入框与快捷输入增加可访问的一键清空，仅清除草稿并恢复焦点，不取消活动下载，不重置画质或目录，保留异步提交的输入保护。
4. 剪辑：默认跟随原视频，读旋转变换后的显示尺寸；常规横屏/竖屏/方形等预设。预览等比完整显示，空余填黑，不拉伸、不默认裁切。预览跟随所选尺寸，导出保持一致；原视频选项保留源显示尺寸/方向。编辑器在常见屏幕高度内可滚动、可调整窗口。导出新 MP4，保留原文件；测试旋转、横竖、方形、速度与导出尺寸组合。

## 发布与验收

- 在新用户隔离设置下验收，不重置用户已有浏览器、目录、历史或会话。
- 原生更新改变 ad-hoc 签名可能使旧隐私授权失配；只在全部检查后一次安装，保留可恢复备份，不放宽签名要求、不自建信任证书。若系统要求认证，由用户本人完成。
- 验证真实下载结果、预览和导出文件尺寸/音轨，区分源页面标称规格与实际文件规格。
- 最终报告分别说明已确认事实、修复项、用户如何操作、独立新 Mac 分发仍需解决的问题。不得以下载成功推断账号登录成功。
