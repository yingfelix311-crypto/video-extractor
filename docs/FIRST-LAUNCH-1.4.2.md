# 1.4.2 首次启动修复

## 问题

1.4.1 的安装包复制了 `limactl`，却没有 Colima 检查的 `lima` 命令，导致首次安装直接失败。单独复制 App 也无法创建后台，因为原有启动代码只会 `docker start metube`；缺失的容器不会被创建。三次短轮询也容易把正常启动误报为服务不可用。

## 修复

- 在发行 App 内携带经校验的完整后台安装器及运行组件。打包器加入 Lima v2.2.0 官方 wrapper；发布物只有一个 App。
- 启动时先检查后台；缺失或未完成初始化时自动继续安装，显示当前阶段，给首次联网初始化最多 20 分钟。
- 只有初始化、依赖及服务检查完成后才允许下载；冷启动等待 30 次，断线后自动重连。
- MeTube 拉取和 pip 安装增加网络重试，保留与容器 ID 绑定的恢复记录。
- 安装器互斥防止并发初始化；`--backend-only` 不复制客户端，不打开第二份 App。旧版命令行安装入口仍兼容；升级备份压成 ZIP，避免产生另一份可见 App。
- 正式 Developer ID 输入禁止被打包脚本静默改为 ad-hoc 签名；完整 payload 的正式签名、公证仍需单独验收。

Lima wrapper 来源：https://github.com/lima-vm/lima/blob/v2.2.0/cmd/lima

SHA256：`88aeac60dbcb69ec675c0ce9af24d5f66255f4899fa73320402db57925500832`

## 发行门槛

运行原生构建与回归、安装器恢复测试、真正打包并解压签名检查，再在干净 Apple Silicon Mac 验证首次打开、离线中断重试、视频/MP3 提取、虚拟机停止后重连。GitHub Actions 构建产物是候选包，不替代 Apple 公证或独立机器验收。旧的 1.4.1 发布附件不会随源码更新自动改变。
